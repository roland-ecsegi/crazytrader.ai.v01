# Pre-T014 adversarial execution architecture review

Separate root review pass before execution implementation; not a separate-model audit.
Authority: AGENTS, EXECUTION_AND_RECONCILIATION, TRADE_INTENT, DATA_AND_LEDGER,
certification and Phase4 evidence. L0 and no owner-local live credentials.

Required repairs/design controls before any adapter invocation:
1. ALLOW is evidence, not capability: load persisted full RiskEvaluationRecord,
   policy hash/current config and authenticated actor; bind exact intent and short
   expiry. No public constructor lets agents submit an SDK order.
2. Serialize tenant journal/order risk, recheck filters/portfolio/source head and
   reserve funds transactionally with durable CREATED/AUTHORIZED/SUBMITTING state.
   Competing approvals must not reuse prior holdings or cap headroom.
3. Persist stable clientOrderId before network send. Restart in SUBMITTING is
   UNKNOWN, never retry. Submission ownership must be fenced/claimed once.
4. Timeout/reset/ambiguous venue error means UNKNOWN with reservation retained;
   explicit rejection alone may release. Nautilus native Binance timeout mapping
   was deferred by foundation spike; cannot silently enable it here.
5. Reconciliation finds by stable client/venue IDs, verifies identity/quantities,
   ingests fills idempotently and resolves only with authoritative evidence.
   Not-found once does not prove absence. Controlled retry requires proven absence,
   current unexpired intent/new risk authorization and new durable request identity.
6. Partial/cancel fills update ledger and reservations idempotently. Never discard
   known venue fill because attribution fails; record suspense/incident, block new
   risk. Terminal execution state alone does not prove all fills posted.
7. Protective cancellation derives ownership from durable registry, no fabricated
   caller proof. AI/OPA outage can use only pinned owner-authorized protective policy.
8. Official SDK isolated unsigned market subprocess is not an execution credential
   boundary. Signed test/live credentials remain owner-local; fixtures cannot
   become live transport. Implement deterministic simulation/fault adapter first.
9. Preserve current LIVE L6+owner guard; known L5/L6 circular requirement remains
   a material owner ADR at local live boundary after independent engineering.

Gate must include actual durable duplicate delivery/restart after submission, timeout
accepted at fixture venue -> UNKNOWN -> recovery exactly one order, partial fill/cancel
accounting, stale policy/intent denial, cap/reservation races and mismatch containment.
