# Phase4 adversarial gate review

Independent root review pass after implementation; not a separate-model or human audit.
Scope: financial direction, trust boundary, policy outage, expiry, immutable replay,
kill controls, cancellation and critical test evidence. Certification remains L0.

Findings and repairs:
- Caller-supplied accounting health/metrics could escape journal-only checks. Bind
  accounting health and scoped mode/symbol/strategy metrics to immutable portfolio
  service facts and current tenant journal head. Missing or changed source denies.
- Context timestamp could outlive older service proofs. Require context observed_at
  at or before venue/portfolio/market safety observations; pure evaluator binds
  expiry to earliest context/portfolio/metadata/market lifetime. Regression added.
- Active owner configuration replacement lacked history. SQL trigger records each
  activation with prior/new versions in append-only history, including direct SQL
  pointer changes; replay same config records no false activation.
- Conflicting facts at equal source timestamp selected nondeterministically. Unique
  source identity plus exact replay validation rejects changed-body collision.
- Re-evaluation could replace a terminal intent decision. Tenant/intent unique
  decision, advisory serialization and changed-record rejection require new intent.
- Cancellation could be mistaken for new untyped exposure. CancellationRequest is
  maintenance of an existing immutable original intent and stable order ID; fresh
  ownership/account/state proof required. UNKNOWN state can cancel known identity,
  never create orders. Actual HTTP/local OPA tests cover degraded protection.
- Lifecycle/certification assertions lack verified registries at this phase. Internal
  boundary refuses above-L0 and lifecycle claims until later verified registries.
  Pure L2 fixtures are explicitly fixtures, not production authority.

Remaining bounded dependencies: Phase5 consumes persisted evidence, rechecks current
state/owner config/filters/expiry and atomically reserves before submission; it must
provide cancellation ownership from actual registry. Phase14 installs scoped writer
roles/service identity/TLS, not trusted-agent booleans. Later certification installs
verified evidence registry. No submission endpoint, credentials or live capability.
These are explicitly future-phase requirements, not completed production readiness.

Final validation references docs/evidence/phase-4-hard-risk.md. No unresolved critical
finding permits unsafe authority in the current L0, internal, non-submitting scope.
